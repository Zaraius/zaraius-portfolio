C Systems Utility

Muteify

I built a small C utility that mutes Spotify ads by polling the Spotify Web API and controlling Linux system audio.

Overview

Muteify mutes system audio when Spotify reports an advertisement and unmutes when music resumes. It is a lightweight, reliable C program I use daily on Linux to avoid interrupted listening during ad-supported Spotify sessions.

Spotify API integration

  • Implemented OAuth 2.0 token flow and token retrieval helper (Python token getter included in repo).
  • Polls Spotify's /v1/me/player endpoint at a configurable interval (default: 10s) to read currently_playing_type.
  • Detects transitions between track and ad to decide mute/unmute actions.
  • Handles bearer tokens in Authorization header for each request using libcurl.

C systems programming

  • Core implementation in C, built with CMake.
  • Uses libcurl for HTTP requests and cJSON for parsing responses.
  • Simple, robust polling loop with signal-handling for clean shutdown.
  • Static configuration and logging kept minimal to remain usable as a personal utility.

Operating system interaction

Muteify controls PulseAudio via the pactl CLI to mute and unmute the default sink:

pactl set-sink-mute @DEFAULT_SINK@ 1  # mute
pactl set-sink-mute @DEFAULT_SINK@ 0  # unmute

This approach uses existing system tools instead of adding a low-level audio driver dependency. It keeps the project small and portable across Linux machines running PulseAudio.

Engineering tradeoffs & limitations

  • Polling interval (default 10s) trades latency for API rate limits, so short ads may play before the next check.
  • Depends on Spotify Web API availability and active playback context; not intended for headless server use.
  • Linux + PulseAudio specific; other platforms are out of scope.

Practical result

This is a personal utility I built and use. It turned a class exercise into a day-to-day tool by integrating C systems programming, web APIs, and OS-level control.
